## Architecture decisions

- Read relevant accepted [ADRs](docs/source/decisions/index.rst) before changing the design.
- Add an ADR only for a major design choice that sets lasting constraints or is costly to reverse. Explain realistic alternatives and tradeoffs.
- Keep routine fixes, refactors, small API changes, and dependency or tooling updates in pull requests. Use the decision index for the template and lifecycle.
